Control de temperatura en una cadena de frío farmacéutica

Actor y contexto

Usted trabaja como ingeniero de datos en PharmaLogix, una empresa que almacena y transporta vacunas, insulinas, reactivos de laboratorio y otros productos farmacéuticos que deben conservarse dentro de rangos de temperatura controlados. La operación incluye un centro principal de distribución, bodegas regionales y vehículos refrigerados que entregan los productos a hospitales y farmacias.

Cada cámara y vehículo cuenta con sensores que envían lecturas periódicas. Una lectura representa la temperatura observada en un momento de la operación y recibe un identificador único. El sistema debe conservar el producto, el centro donde se registró la lectura, la etapa logística y la temperatura medida para que el equipo de calidad pueda reconstruir la historia de un lote.

El equipo de logística consulta una lectura específica cuando una alarma se activa, mientras que el equipo de calidad revisa conjuntos de registros durante las auditorías. El supervisor necesita distinguir entre una temperatura normal, una lectura cercana al límite y una desviación crítica que podría obligar a inmovilizar un lote. Una lectura duplicada no debe incorporarse porque podría alterar la trazabilidad del lote y generar dos versiones del mismo evento.

El sistema mantiene un histórico en memoria y recibe nuevas lecturas al inicio de cada jornada desde los dispositivos de monitoreo. La aplicación debe responder con rapidez a las consultas del personal de operaciones y producir recorridos ordenados para los reportes de calidad. El índice se construirá con un árbol binario de búsqueda usando RecordNumber como clave.

Las lecturas nuevas no llegan con una condición calculada. El proceso debe interpretar la temperatura, asignar la condición correspondiente y conservarla junto con el registro antes de insertarlo. Cuando el identificador ya existe, debe mantenerse la lectura histórica y registrarse el rechazo de la nueva lectura.

El resultado será utilizado para decidir si una lectura puede continuar en el flujo logístico, si debe ser revisada por calidad o si requiere una acción inmediata sobre el producto. Las lecturas pueden originarse en una cámara de almacenamiento o durante el transporte. Por esta razón, cada registro debe conservar su identificador, producto, centro, temperatura y etapa logística, y el árbol debe mantener su estructura después de procesar las nuevas lecturas.

Reglas de procesamiento

Condition se calcula a partir de TemperatureCelsius y no debe leerse de las nuevas lecturas:

  1. Si la temperatura es menor que 0 o mayor que 8, la condición es Critical.
  2. Si no se cumple la regla anterior y la temperatura es menor que 2 o mayor que 6, la condición es Review.
  3. En cualquier otro caso, la condición es Normal.

El sistema debe calcular Condition antes de insertar cada registro. Si una lectura nueva tiene un RecordNumber que ya existe, se rechaza y el árbol conserva el registro original.

Reto

Construya una aplicación de consola que:

  1. Cargue los dos archivos JSON mediante el servicio de carga de datos.
  2. Construya el árbol con las lecturas históricas usando RecordNumber como clave.
  3. Antes de procesar las lecturas nuevas, muestre cantidad, altura, hojas, nodos internos y los cuatro recorridos.
  4. Busque la lectura 4500 y la lectura inexistente 9999, mostrando el resultado y el camino recorrido.
  5. Calcule y guarde Condition con las reglas indicadas.
  6. Procese las lecturas nuevas: incorpore las que tengan un identificador no registrado y descarte las que ya existan.
  7. Muestre las lecturas insertadas y rechazadas con su condición calculada.
  8. Muestre nuevamente las métricas y recorridos después de las inserciones.
  9. Verifique que el árbol conserve su propiedad de búsqueda.

Preguntas de análisis

  1. ¿Por qué RecordNumber es una clave adecuada para organizar las lecturas?
  2. ¿Qué riesgo de trazabilidad existe si se acepta una lectura duplicada?
  3. ¿Por qué una lectura fuera del rango debe clasificarse como Critical?
  4. ¿Qué diferencia existe entre Review y Critical según las reglas?
  5. ¿Qué información permite observar el recorrido por niveles?
  6. ¿Qué cambios pueden producir las nuevas inserciones en la altura y los recorridos?
